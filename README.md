# Book Wiki Reader Skill

Book Wiki Reader 是一个面向 Codex 的读书 skill。它的目标不是“帮你快速总结一本书”，而是把一本书真正读进你的个人知识系统里。

很多 AI 读书工具会停在摘要层面：它们能告诉你一本书讲了什么，却很难帮你判断哪些观点值得相信、哪些内容和你有关、哪些想法应该被长期保存。Book Wiki Reader 想解决的是另一个问题：

> 读完一本书之后，怎样把它变成自己的理解、判断、主题、方法和想法？

它会把“读书”拆成一套可执行流程：先入库，再介绍，再检视，再共读，最后总结和分流。读者不需要从零整理笔记，也不需要被一堆问题审问；AI 会先承担读解、压缩和结构化工作，再把关键判断交还给读者。

## 它适合谁

- 想认真读书，但不想每次都从空白笔记开始的人
- 想建立个人读书知识库、第二大脑或长期记忆库的人
- 想让 AI 陪自己读书，而不是只要一份摘要的人
- 想把书里的观点转化成写作、研究、项目、方法论的人
- 想做主题阅读、跨书比较、观点积累的人
- 想把读书过程产品化、流程化、skill 化的人

## 它能帮你得到什么

使用这个 skill 后，一本书不会只留下零散划线或一篇摘要，而是会被整理成一组可复用资产：

- **Book note**：这本书的结构、核心问题、作者主张、论证和你的判断
- **Reading map**：这本书的目录、骨架、重点章节和阅读路线
- **Theme card**：可以跨书复用的主题，比如学习方法、知识管理、AI、写作、商业判断
- **Idea card**：你在阅读中产生的新想法、项目灵感、文章选题或方法论
- **Author card**：重要作者的长期关切和主要观点
- **Reading plan**：围绕一个问题继续读下去的路线
- **Raw archive**：原始文件、来源记录、长文本分块和可追溯材料

最终效果是：你不是“读过一本书”，而是让这本书进入你的知识网络。

## 核心亮点

### 1. 先判断用途，再决定读法

不是每本书都值得逐章深读。Book Wiki Reader 会先帮助你判断这本书适合精读、跳读、围绕问题读、只整理入库，还是直接放弃。

### 2. 先检视，再共读

正式读之前，它会先给你书籍介绍、目录、骨架地图和阅读建议。你会先知道这本书是什么、值不值得读、应该怎么读，而不是直接进入漫长摘要。

这些内容必须直接显示在对话里，而不是只生成一个文件让你自己打开。文件和 wiki 是沉淀层，聊天里的目录、骨架和阅读建议才是阅读入口。

### 3. 不被章节绑架

共读的基本单位不是章节，而是问题块、观点块、论证块或方法块。一章可能有多个关键观点，也可能只是铺垫；这个 skill 会围绕真正有价值的阅读单元推进。

### 4. AI 先读解，读者再赋义

AI 负责把文本读清楚：

1. 这个单元在解决什么问题？
2. 作者给出的答案是什么？
3. 这个答案凭什么成立？有哪些论证和例子？

然后把最重要的问题交给读者：

4. 这可能和你有什么关系？

这能避免 AI 假装懂你，也能避免读者被迫从零表达。AI 先搭桥，读者决定意义。

### 5. 提问不是为了互动，而是为了触发思考

它不会反复问空泛的“你怎么看”。每个阅读单元只问一个主问题，并根据内容类型选择问题：概念问理解，主张问判断，论证问证据，方法问应用，长期有价值的观点问怎么入库。

### 6. 只保存未来会被调用的东西

Book Wiki Reader 不鼓励把所有内容都塞进笔记。它会帮助你判断哪些内容值得进入 book note，哪些应该变成 theme card、idea card、method 或 reading plan。这样知识库不会变成摘要堆，而会慢慢长成你的思想索引。

### 7. Context stacking：长书也不会撑爆上下文

一本书可能有几十万字，不应该一次性丢进模型。Book Wiki Reader 会把原文保存在 raw 里，并把纯文本切成可追溯的 `chunks/` 分块和 `chunk-index.md` 索引。检视阅读时先看索引和关键片段；正式共读时每次只读取当前问题块需要的少量分块，读完再压缩进 wiki。

它不是简单切块，而是分层保存上下文：

- 原文层：完整文件和分块，只在需要证据时读取
- 分块摘要层：每个 chunk 的关键概念、主张、例子和位置
- 阅读单元层：问题块、观点块、论证块或方法块
- 章节/部分层：这一部分的核心问题、答案和论证路线
- 全书骨架层：整本书的主线、薄弱点和可复用资产

这样每次对话只带高层上下文，需要细节时再下钻到原文，既省 token，又不把重要证据彻底丢掉。

这里要诚实一点：context stacking 不是“完全不读全文也能懂全文”。它有两种模式：

- **快速检视**：只读目录、前言、结论、章节首尾和关键分块，生成初版骨架。适合快速判断值不值得读、怎么读，但骨架是暂定的。
- **全书索引**：顺序扫完整本书的 chunks，每次只处理一小块，压缩进 stack 后释放原文上下文，最后生成校准骨架。第一次会花更多 token，但后续共读、总结和入库会省很多。

所以它省的不是“第一次阅读成本”，而是“不让全文同时进入上下文，并避免每次讨论都重新搬运全文”。

## 安装

把这个仓库克隆或下载到你的 Codex skills 目录：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/ginbrooks/book-wiki-reader-skill.git ~/.codex/skills/book-wiki-reader
```

如果你下载的是 zip 文件，解压后把文件夹放到：

```text
~/.codex/skills/book-wiki-reader
```

然后重启 Codex，或者开启一个新会话，让 Codex 重新发现这个 skill。

## 使用方式

你可以这样说：

```text
用 $book-wiki-reader 把这本书读进我的 Book Wiki。
```

或者更口语一点：

```text
按 Book Wiki 读这本书。
```

如果你提供的是本地书籍文件，可以用脚本初始化 wiki 条目：

```bash
python3 ~/.codex/skills/book-wiki-reader/scripts/init_book_wiki.py \
  --root ~/Documents/Book-Wiki \
  --source "/path/to/book.txt" \
  --title "书名" \
  --author "作者"
```

脚本会创建：

- `raw/books/<book-slug>/original/<source-file>`
- `raw/books/<book-slug>/source.md`
- `raw/books/<book-slug>/chunk-index.md`
- `raw/books/<book-slug>/chunks/chunk-0001.md`
- `raw/books/<book-slug>/stack/`
- `wiki/books/<book-slug>.md`

默认会把 txt/md 纯文本切成约 8000 字符一个分块。PDF、EPUB、DOCX 等格式建议先转换成 txt 或 md，再导入转换后的文本。

## 默认 Wiki 结构

这个 skill 默认使用下面的结构：

```text
Book-Wiki/
  raw/
    books/
      <book-slug>/
        original/
        chunks/
        stack/
        chunk-index.md
        source.md
    inbox/
  wiki/
    books/
    themes/
    ideas/
    authors/
    reading-plans/
  templates/
```

## 阅读流程

1. **入库**：保存原始文件和来源记录。
2. **分块索引**：长文本切分到 `chunks/`，用 `chunk-index.md` 定位内容。
3. **Context stack**：维护分块摘要、阅读单元摘要、章节摘要、全书骨架和读者记忆。
4. **书籍介绍 + 轻量检视**：先展示一句话简介、目录摘要、初版骨架、核心问题和阅读建议。
5. **用途确认**：判断你想怎么用这本书。
6. **检视阅读**：必要时补充更完整目录、骨架、重点判断和阅读建议，并标注骨架可信度。
7. **确认读法**：从头读、挑重点、围绕问题读、只整理入库，或放弃。
8. **正式共读**：按问题块或观点块推进，用三问读解卡读懂文本。
9. **读者赋义**：把“这和我有什么关系”交给读者确认。
10. **总结入库**：只把未来还会调用的内容沉淀进 wiki。

第一次阅读入口应当在聊天正文里出现：

- 一句话简介
- 原始目录或目录摘要
- 初版骨架
- 核心问题
- 章节/单元价值判断
- 阅读建议
- 下一步选择问题

## 骨架可信度

Book Wiki Reader 会区分三种骨架：

- **初版骨架**：来自快速检视，用来决定读法，不当成最终结论。
- **校准骨架**：来自全书 chunk 摘要，更适合全书总结和主题分流。
- **修订骨架**：来自共读和用户讨论，包含读者自己的判断、不同意和迁移想法。

## 三问读解卡

AI 负责回答：

1. 这个阅读单元在解决什么问题？
2. 作者给出的答案是什么？
3. 这个答案凭什么成立？有哪些论证和例子？

读者负责回答：

4. 这可能和我有什么关系？

## 和普通 AI 摘要有什么不同

普通 AI 摘要更像“读完后给你一份报告”。Book Wiki Reader 更像“陪你建立一套读书系统”。

| 普通摘要 | Book Wiki Reader |
| --- | --- |
| 快速压缩内容 | 帮你判断内容是否值得保存 |
| 主要复述作者观点 | 区分作者观点、AI 判断和读者观点 |
| 按章节总结 | 按问题块、观点块、论证块推进 |
| 容易被长文本撑爆 | 先分块建索引，再按需读取 |
| 读完就结束 | 读完后分流到 book/theme/idea/plan |
| 笔记容易堆积 | 只保存未来会被调用的资产 |

## 当前状态

这是一个可用的 skill MVP，适合个人使用、小范围测试和继续迭代。它已经包含：

- Codex skill 说明文件
- Book Wiki 共读流程
- book/theme/idea/author/reading-plan 模板
- 本地书籍初始化脚本
- 长文本自动分块和索引生成

后续可以继续扩展：

- 更好的 PDF / EPUB / DOCX 转文本流程
- 更强的主题卡自动合并
- 更多书籍类型的阅读策略
- 面向普通用户的前端界面

## 原则

- 作者观点、AI 判断、读者观点要分开。
- 只保存未来可能复用的内容。
- 保留 raw 来源，方便追溯。
- 对书籍做总结和分析，不复制大段受版权保护的原文。
